While much did not change on the Login screen, there was one addition. As the app's backend is deployed to Render, on app load, the Android app pings the server to wake it up, and a spinner and message are displayed as the app waits for a repsonse. Likewise, while waiting, the create and login buttons are disabled to prevent failed login or registration attempts.

Dashboard

Original

Final

The dashboard activity highlights several key differences between the original and enhanced application. Originally, the toolbar served only as a static label, item cells displayed only their names and quantities and were confined to a fixed three-column grid layout, and each cell contained its own delete button.

The enhanced version expands the toolbar with a search icon, hamburger menu, and overflow menu. A category ChipGroup now dynamically populates with the current inventory categories, enabling quick filtering. The per-cell delete button has been removed in favor of an Action Mode where long-pressing an item activates a Contextual Action Bar, providing support for both single and batch deletions. Finally, the default layout has been changed to a two column layout from three, adding more space to accomodate the addition of the price field, and modifying the currency and quantity labels for clarity.

When migrating from Room to MongoDB, I took the opportunity to expand the data model with additional fields, SKU, price, date created/modified, and category, to make inventory records more descriptive. These schema changes required updating the Android app accordingly, with the item dialog fragments revised to display, accept, and submit the new fields.

Android New Features

Overflow Menu

Sort BottomSheet

List View

These screenshots illustrate the overflow menu and its functionality. The first image shows the dropdown that appears when the overflow icon is tapped, revealing the available options. Selecting "Sort" opens a bottom sheet allowing users to sort inventory by name, category, date added, or price, in either ascending or descending order. Selecting "Toggle Layout" switches the default two-column card grid to a single-column list view, where each item displays its name, category, quantity, and price. This alternate layout helps users with larger inventories quickly scan and compare items without having to open each one individually.

Navigation Drawer

Settings Activity

The left screenshot displays the newly added navigation drawer, which provides options to exit the app, log out, and access settings. Exit closes the app, logout clears the user's JWT and returns them to the login screen with back navigation disabled, ensuring subsequent access attempts require reauthentication. The right screenshot shows the settings activity, where users can adjust text size, toggle light and dark themes, and manage notification and permission settings.

Search

These screenshots showcase the search, filtering, and suggestion features of the dashboard. The first screenshot demonstrates the prefix trie powering search suggestions. As the user types in the search bar, the input is matched against a trie populated with all inventory item names, and the results are displayed in a dropdown list for quick selection. Tapping a suggestion runs a search for that item. Completely New

Angular App

This is the landing page of the Angular application, which provides search, category filtering, sorting, and the ability to add, edit, and delete items. By default, all data and functionality are hidden until the user authenticates.


This screenshot shows the login form, which accepts a username and password. Basic validation is enforced, preventing submission if either field is empty.


Upon successful login, the data table is populated, full functionality is enabled, and the login button is replaced with a logout button.


Selecting an item enables the edit and delete buttons for that entry. Selecting multiple items allows users to batch delete inventory records.


Clicking edit with an item selected opens a form pre-populated with that item's current values. The user can modify any fields and either save the changes to the database or discard them and return to the dashboard.


Searching in the Angular app mirrors the Android app, it queries the database with the provided name and returns only matching results for display.


The add item form mirrors the edit form but starts empty, allowing users to fill in the details for a new item and save it to the database, or discard and return to the dashboard.


Category filtering in the Angular interface is handled via a dropdown populated with the current inventory categories. Selecting one filters the results to only items belonging to that category.


The final screenshot shows the sort functionality sorting the results by price in descending order.
